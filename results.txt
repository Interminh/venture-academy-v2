PARENT FRONT
------------

1. "Home in top right instead of Log in + Sign up" — DONE.
   The landing page header now checks if you're logged in and shows a
   "Home" button (straight to your dashboard) instead of Log in/Sign up.
   Applies to all three account types, since it's just "is anyone logged
   in," not role-specific.

2. Student first name → full name — DONE (from last session, still holds).
   The field is labeled "Student's name" and takes whatever you type. I
   left the database column named first_name internally since renaming it
   is a bigger, riskier change than the actual request — nothing user
   facing calls it "first name" anymore.

3. "Edit availability gives a blank screen instead of existing values" —
   FOUND THE BUG, FIXED. This was real and I'm glad you caught it: the
   database stores times like "16:00:00" (with seconds), but the checkbox
   grid was built using "16:00" (no seconds). They never matched, so every
   existing slot looked unchecked when you opened Edit — and, worse, the
   same mismatch meant *saving* an edit was quietly trying to re-insert
   slots that already existed and erroring out. Both are fixed now
   (lib/utils/slots.ts's new toHHMM() normalizes it everywhere).

4. "What happens if you change availability while pending/booked — should
   auto-cancel" — DONE, but this needed a real schema fix underneath it,
   not just a tweak:
     - Parents previously had zero ability to cancel a claim at all (only
       tutors and admins could). Added that permission, scoped to your own
       kids only (migration 0008).
     - Removing a slot used to hard-delete it from the database, which
       would have erased that claim's history along with it — breaking the
       "claims are never deleted" rule the rest of the app already
       promises (e.g. the Ledger page depends on this). So slots are now
       "soft deleted" (marked inactive, not actually removed), which keeps
       every claim's history intact permanently while still letting the
       slot disappear from your schedule and the tutor's view.
   Net effect: uncheck a slot that's pending or booked, and that claim
   gets cancelled automatically — the tutor sees it drop off their claims
   list, same as if they'd cancelled it themselves.

5. "Sessions tab with tutor name/email once booked" — DONE. New "Sessions"
   tab on the parent side, next to "My students." Lists every confirmed
   booking across all your kids with the tutor's name and email attached.
   This needed a new permission too (migration 0010) — previously there
   was no way for a parent to even read a tutor's contact info from the
   database, only the reverse (tutor seeing parent info).

6. "Max sessions per week, fully booked once reached" — DONE. Optional
   field on the student form ("no limit" if left blank). Once approved
   bookings hit that number, the student shows a "Fully booked" badge —
   on your dashboard and on the tutor's browse screen. Per your note, I
   didn't make it a hard block on new claims, just a visible flag — a
   director can still see and approve one over the cap if that's ever the
   right call.

7. "Additional Information free-text box" — DONE, and cheaper than
   expected: the database already had a notes column from the original
   schema, just never exposed anywhere. Added a textarea to the student
   form and it now shows quietly under the student's name on your
   dashboard (only if you actually wrote something).
